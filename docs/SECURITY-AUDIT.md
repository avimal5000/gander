# Sway macOS security audit

Date: 2026-10-30. Read-only review. No file in the repo was changed and no git state was changed.

## Scope

- Sway/ (app target: SwayApp.swift, AppComposition.swift)
- SwayCore/Sources (all modules: CameraService, PoseEstimator, PoseTraces, DisplayTracker, FocusControl, SwitchEngine, SystemIntegration, SwayUI, SwayModels)
- Config/ (Info.plist, Sway.entitlements)
- Sway.xcodeproj/project.pbxproj build settings
- scripts/ (privacy-guard, audit-privacy, release, soak, sleep-diag, seed-github)
- .github/ (ci.yml, release.yml, dependabot.yml)
- docs/PRIVACY-AUDIT.md, docs/RELEASING.md

Not covered in depth: SwayUI views, tests, the Vision pose math, and the contents of the gitignored .build-* directories.

## Method

Static reading only. I read the privacy docs and both audit scripts first. Then I grepped the shipped sources for logging, UserDefaults, file I/O, Process/NSTask, unsafe or unmanaged pointers, `try!`, `as!`, `fatalError`, numeric-conversion traps, notifications and networking. I read the following files in full: the focus stack, the Carbon hotkey registry, the login item, the trace store, the model Codable decoding, the camera controller header and lifecycle, the workflows and `release.sh`. I did not run the app, the tests, the guard or the audit script. Anything marked "not executed" below is reasoned from code.

## Things verified clean

- Entitlements: `Config/Sway.entitlements` holds only `com.apple.security.device.camera`. There is no sandbox (documented and justified), no network entitlement, and no `cs.allow-*` exception. `ENABLE_HARDENED_RUNTIME = YES` is set in both target configs (the pbxproj lines read), and `release.sh` re-signs with `--options runtime --entitlements`.
- Usage strings and permissions: `NSCameraUsageDescription` is present and accurate. No microphone, input monitoring or screen recording keys. Accessibility is requested only from the Focus Test action (`AppModel+FocusTest.swift:158`). `LSUIElement` is set.
- Network: no `URLSession`, `URLRequest`, sockets, WebKit or `Network` use in Sway/ or SwayCore/Sources. The only `URL(string:)` calls are two `x-apple.systempreferences:` deep links opened with `NSWorkspace`. No Sparkle or updater, no URL scheme, no XPC, no mach ports. `SwayCore/Package.swift` has no external dependencies, so there is nothing to pin and no `Package.resolved`.
- Camera frames: no `AVAssetWriter`, `AVCapturePhotoOutput`, image encoders or pixel writes in the shipped sources. Frames go to Vision through `FrameSampleReceiver`. `FileTraceStore.save` writes numeric `PoseTrace` JSON and is compiled out of Release builds.
- Input events: no event tap, global monitor, `CGEventPost` or IOHID. The only hotkey path is Carbon `RegisterEventHotKey`. The hotkey registry is lock-protected, the handler is unregistered in `deinit`, the unretained `userData` cannot outlive the owner, and `isValid` requires Control, Option or Command.
- Private APIs: none found. `unsafeDowncast` in `AXElementAccess` is preceded by a `CFGetTypeID` check; `unsafeDowncast` in the AXValue readers has the same check; the Carbon `Unmanaged` use is sound. `WindowServerList` uses only the public CGWindowList call with owner, layer and bounds.
- Process execution: no `Process`, `NSTask` or `NSAppleScript` in the app. Shell scripts use no `eval`, `curl`, `wget` or `sudo`, and `rm -rf` is limited to fixed build paths.
- Window titles: AX titles are read only for the focus summary and the Focus Test row. They are not logged (checked every `Logger` call), and the privacy docs claim only that switch logs name the app and display, which holds.
- Corrupt stored settings: `storedLibrary`, `storedSensitivity` and `storedFocusLockShortcut` use `try?` with safe defaults. A wrong-typed value reads back as nil, the library decoder drops bad profiles and old format versions, and no `try!`, `as!` or force unwrap on external input was found in shipped sources. `fatalError` appears only in unused `init(coder:)`.
- Camera lifetime: the camera controller serializes all state on one queue, and `stop()` is queued behind `start`. Sleep, lock and display-sleep reasons are sticky, and `applicationWillTerminate` stops the pose source and camera (and process exit ends capture anyway). I found no path that leaves the camera on with Tracking off, by reading; this was not exercised at runtime.
- Login item: `SMAppService.mainApp` register and unregister, with errors surfaced. No LaunchAgent plist or helper tool.
- Workflows: `ci.yml` runs on `pull_request` (not `pull_request_target`) with `permissions: contents: read` and no secrets. `release.yml` validates the tag format, so `GITHUB_REF_NAME` injection is not possible, and deletes the keychain in an `always()` step. `dependabot.yml` covers GitHub Actions.
- Git history: no private-key or token strings found by the greps I ran (`BEGIN PRIVATE`, `ghp_`, `AKIA`), and no secrets in tracked files outside docs.

## Prioritized fix list

1. S1: protect the release job (Environment with required reviewers, tag protection, SHA-pin actions, fail instead of ad hoc fallback).
2. S2: replace `Int(x.rounded())` with a safe conversion, validate decoded layouts, and cap trace file size.
3. S3: make app names `.private` in the logs and update the privacy doc.
4. S7: extend the privacy guard (missing patterns, `Package.swift`, entitlements) and run the full static audit in CI.
5. S4 and S5: keychain profile for notarytool, and `-T` instead of `-A` for the p12 import.
6. S9 and S10: validate stored profile scales and non-finite settings.
7. S6, S8, S13: ship only notarized builds, tighten trace permissions and the doc wording, extend `.gitignore`.
8. S11, S12, S14, S15: optional hardening and documentation.
